# 업무일지 디자인·동작 규칙

> 상태: **확정 (2026-10-02).** 사용자가 결정 D1~D7을 "추천대로"로 승인함.
> 새 기능을 만들거나 고칠 때 이 문서를 먼저 확인하고, 규칙과 다르게 해야 하면 이 문서를 같이 고친다.
> 근거 수치는 2026-10-02 현황 조사(폰 390px·PC 캡처, 코드 집계, 직접 측정)에서 가져왔다.

## 확정된 결정

| # | 결정 |
|---|---|

## 1. 삭제와 되돌리기  (조사 A군: 데이터 안전)

1. **모든 "삭제"는 되돌릴 수 있어야 한다.** 되돌리기 없는 즉시 영구 삭제를 만들지 않는다.
   - 일지·빠른 기록: 휴지통 이동(기존 유지), 휴지통에서 복원 가능.
   - 할 일·기억할 것: 4.5초 되돌리기 토스트 후 확정 (D1).
2. **확인창은 되돌릴 수 없는 작업에만** 쓴다: 영구 삭제, 여러 건 일괄 삭제, 저장소 전환, 연결 해제, 가져오기 덮어쓰기.
   단건 삭제는 확인창 대신 "되돌리기" 토스트 (D2).
3. **버튼 이름이 결과를 말해야 한다.**
   - 휴지통으로 가는 것: 라벨 "삭제"(아이콘 휴지통) — 확인창/토스트 문구에 "휴지통으로 이동" 명시.
   - 완전히 지워지는 것: 라벨 "영구 삭제" — 반드시 확인창.
   - "제거"는 첨부(사진·링크·항목) 빼기에만 쓴다.
4. 삭제 실패 시: 데이터는 그대로 두고 "삭제 실패: 사유" 토스트에 **다시 시도** 버튼.

현재 위반: 메모 즉시 영구 삭제, 삭제 방식 4종 혼재.

## 2. 카드·목록 행의 버튼  (조사 C군)

1. **순서 고정**: [즐겨찾기(있는 경우)] [수정 ✎] [삭제 🗑]. 할 일은 [완료 체크(왼쪽)] … [캘린더 추가] [수정] [삭제].
2. **삭제 아이콘은 휴지통만.** X는 "닫기"와 "첨부 빼기"에만 쓴다. (현재 할 일·메모가 X → 휴지통으로)
3. **크기**: 아이콘 16px, 버튼 터치 영역 최소 40×40px(D6). 현재 27~32px.
4. **항상 보인다.** 마우스 올릴 때만 나타나는 버튼 금지(D7). 선택 모드에서만 숨김(기존 `wj-card-actions` 유지).
5. 같은 모양의 버튼은 **공용 컴포넌트**로만 만든다(아래 8번). 줄마다 클래스를 복사해 만들지 않는다.
   - `IconButton`: 카드·행·머리글·창 닫기의 아이콘 버튼 (40×40, 아이콘 16px, tone: default/danger/accent/star-on/success)
   - `TextAction`: 도구 줄·폼의 작은 텍스트 버튼([선택] [휴지통] [필터 초기화] [+ 항목 추가], 높이 40px)
6. 폼 안의 글자 서식 보조 버튼([B 강조])은 높이 32px 이상, 글자 라벨을 함께 보인다.
7. **토스트는 하단 탭 바 위에 뜬다**(탭 바를 가리지 않음, 폰·PC 모두).
8. 인접한 아이콘 버튼의 누르는 영역은 서로 겹치지 않는다.

## 3. 글자 크기·색 대비  (조사 B군)

1. **글자 크기 단계는 5개만**: 11 / 12 / 13 / 14 / 15px (+ 앱 제목 1개). **10px 이하 금지**(현재 10px 13곳, 9px 2곳).
2. 본문·값: `slate-700` 이상. 라벨·보조(날짜·시각·설명): **`slate-500` 이상**(대비 4.7:1). `slate-400` 글자 금지(현재 2.6:1, 60여 곳).
3. 아이콘 버튼: **`slate-500` 이상**, 호버 시 `slate-700`. `slate-300` 금지(현재 1.5:1). 비활성(disabled)만 예외.
4. 다크 모드도 같은 기준: 보조 글자 `slate-400` 이상, 아이콘 `slate-400` 이상.
5. 새 화면은 캡처해서 폰(390px) 기준으로 직접 눈으로 확인한다.
6. **예외(브랜드·데이터 색, 이번 단계에서 건드리지 않음)**: 카테고리 색 글자/배지, 즐겨찾기 별(amber), 알림 개수 배지(흰 글씨/빨강), 달력의 토·일 색.
   이 색들은 흰 배경에서 2~3:1이라 별도 결정이 필요함(진하게 조정할지) — 표기 단계에서 다시 다룬다.
7. **자동 감시**: `tests/rules-readability.js`(가독성)와 `tests/layout.js`(버튼 크기·삭제 아이콘·도구 줄·토스트 위치)가 규칙 위반을 잡는다. 가독성 감시는 라이트/다크 × 주요 7개 화면에서 회색 글자(4.0 이상)·아이콘(3.0 이상)·11px 미만 글자를 측정해 위반 시 실패시킨다.
   (테스트 환경은 Tailwind v4 팔레트라 운영(v3)과 색이 아주 조금 달라 기준에 여유를 둠. 운영 `slate-500`은 흰 배경 4.76:1)
8. 항상 어두운 화면(첫 연결 화면, 토스트, 사진 확대, 어두운 배경 위 닫기 버튼)은 밝은 글자를 쓰므로 위 색 규칙에서 제외한다.

## 4. 목록 위 도구 줄  (조사 C군 #11)

모든 목록 탭은 같은 구조: **왼쪽 = 개수·필터 상태, 오른쪽 = [선택] [휴지통]** 한 줄. 순서 고정(선택 → 휴지통).
휴지통이 없는 탭(할 일·기억할 것)은 [선택]만, 위치는 동일. 기억할 것에도 [선택]이 필요한지는 별도 결정.

## 5. 날짜·시각 표기  (조사 D군)

| 용도 | 형식 | 예 |
|---|---|---|
| 날짜 | `YYYY.MM.DD (요일)` | `2026.10.02 (금)` |
| 시각 | 24시간 `HH:mm` | `14:32` |
| 날짜+시각 | 둘을 공백으로 | `2026.10.02 (금) 14:32` |
| 보조 줄(작성/수정/삭제) | `작성 MM.DD HH:mm` (올해), 작년 이전은 `YYYY.MM.DD HH:mm` | `수정 09.30 09:05` |

- 화면에 **ISO(`2026-10-02`)·`mm/dd/yyyy` 직접 노출 금지**(저장 값에만 사용). 현재 타임라인 범위 표시가 ISO.
- "삭제됨"도 날짜+시각을 표시한다(현재 날짜만).
- 날짜 계산용 함수는 `fmtDateShort / fmtTime / fmtStamp` 세 가지만 쓴다. 화면에서 직접 `toLocale…`로 만들지 않는다.

## 6. 용어집  (조사 D군 #15)

| 용어 | 뜻 | 쓰지 않는 말 |
|---|---|---|
| 일지 | 업무일지 한 건 | 기록(모호) |
| 빠른 기록 | 탭 이름. 그때그때 적는 한 줄 메모 | |
| 정리됨 | 빠른 기록을 일지로 옮겨 적은 상태 | 완료, 처리됨 |
| 기억할 것 | 태그로 찾는 상시 메모 (D3) | 메모, 기록할 것 |
| 휴지통 / 복원 / 영구 삭제 | 삭제 후 복구 가능 / 복구 / 되돌릴 수 없음 | 완전히 삭제 |
| 보관 레포 | 지난 연도 데이터 저장소(읽기 전용) | 아카이브 |
| **강조** | 글자를 굵게+밑줄로 표시(`==글자==`) | 하이라이트 |
| **하이라이트** | 탭 이름: 즐겨찾기·중요도 상 모음 | |
| 검색 표시 | 검색어에 칠해지는 주황 배경 | 강조 |

새 용어는 이 표에 먼저 추가한 뒤 쓴다.

## 7. 팝업·모달  (조사 E군 #17)

1. **팝업은 앱 전체(App) 수준에 정의한다.** 특정 탭 안에 정의하지 않는다. (이번 세션에서 빠른 기록 수정창이 탭 안에 있어 생긴 버그가 이 규칙의 근거)
2. 종류: **수정** = 오른쪽 서랍(모바일은 전체 화면) / **미리보기** = 가운데 카드 / **확인** = 브라우저 확인창(D4: 교체는 나중).
3. 닫기: X, Esc, 뒤로가기, 바깥 클릭이 모두 동작한다. 내용이 바뀐 수정창은 닫을 때 확인한다(기존 유지).
4. 새 팝업을 만들면, **어느 탭에서 열어도 열리는지** 테스트에 넣는다.

## 8. 코드 규칙  (조사 E군 #18)

1. 같은 모양이 두 번 이상 나오면 공용 컴포넌트로 만든다: `IconButton`, `TextAction`(작은 텍스트 버튼), `ToolbarRow`(4번 도구 줄), `StampText`(작성/수정 시각).
2. 둥글기: 입력·버튼·카드 `rounded-lg`, 칩·배지 `rounded-md` 또는 `rounded-full`. 그 외 금지(현재 `rounded`, `rounded-xl`, `rounded-[2px]` 혼재).
3. 색은 slate 계열 + 지정된 포인트색(카테고리색, 주황 `#E8A93B`, 경고 `#F0654A`)만. 새 색을 쓰려면 이 문서에 먼저 추가.
4. 한 번에 한 묶음만 고친다: (a) 안전 (b) 가독성 (c) 배치 (d) 표기 순서. 서로 다른 묶음을 한 PR에 섞지 않는다.

## 9. 문구 톤

해요체. 토스트는 `~했어요` / `~실패: 사유`. 확인창은 **무엇을 → 어떻게 되는지 → 되돌릴 수 있는지** 순서로 쓴다.
예: `"서버 점검" 일지를 휴지통으로 옮길까요? 휴지통에서 복원할 수 있어요.`

## 10. 새 기능·수정마다 점검할 상황

빈 목록 / 아주 긴 글 / 줄바꿈 / 폰 390px / 다크 모드 / 읽기 전용(보관 레포) / 오프라인 / 저장 실패(토스트+다시 시도) /
연타 / 다른 기기가 먼저 수정(409) / 어느 탭에서 열어도 동작하는가.

## 11. 규칙이 지켜지는지 자동 검사 (제안)

`tests/`에 "규칙 감시 테스트"를 추가해 위반이 생기면 병합 전에 실패하게 한다.
- 아이콘 버튼 최소 크기 40px
- 글자 최소 11px, 보조 글자·아이콘 대비 기준
- 호버 전용 버튼 없음(터치 화면 크기에서 카드 버튼이 보이는가)
- 화면 어디에도 ISO 날짜 문자열이 보이지 않음
- 모든 팝업이 모든 탭에서 열림
(색 대비는 이 환경의 브라우저에서 측정 가능함을 확인했음. 단, 폰 실기기 확인은 별도.)

## 적용 순서와 진행 상태

1. **안전**: 메모·할 일·일지·빠른 기록 되돌리기, 삭제 문구 정리 (규칙 1) — **완료 (ver.36)**
2. **가독성**: 글자·아이콘 색과 크기 (규칙 3) — **완료 (ver.37)**
3. **배치**: 삭제 아이콘 통일, 버튼 크기, 항상 보임, 도구 줄 위치 (규칙 2, 4) — 진행 중(ver.38)
4. **표기**: 날짜 형식, 용어 통일 (규칙 5, 6)
5. **구조**: 공용 컴포넌트화, 규칙 감시 테스트 (규칙 8, 11)

각 단계는 별도 PR로 나누고, 단계마다 전체 회귀 테스트와 캡처 확인을 거쳐 병합합니다.
